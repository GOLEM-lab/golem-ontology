
## GOLEM quality pattern

### Solution 1 - via DLP

1) Remove `golem:G2_Feature` and align `golem:G17_Character_Feature` and `golem:G18_Textual_Feature` to `dol:abstract-quality`, since the latter is the correct quality class when it comes to `dol:non-physical-endurant` objects.
2) Narrow down the domain class of property `golem:GP0_has_feature` to `ecrm:E28_Conceptual_Object` and set its range class as the logical union of `golem:G17_Character_Feature` and `golem:G18_Textual_Feature`.
   Do the same for its inverse property and align it to `dol:inherent-in`.
3) Fix class numbering, since `golem:G2_Feature` doesn't exist anymore.




### Solution 2 - via DUL Region pattern (adopted)

1) Import `http://www.ontologydesignpatterns.org/cp/owl/region.owl`, an ODP for Regions modeling extracted from DUL+Dns.
2) Create dedicated prefix: `dul_region`.
3) Align `golem:G2_Feature` to `dul_region:Region`, `golem:GP0_has_feature` to `dul_region:hasRegion` and `golem:GP0i_is_feature_of` to `dul_region:isRegionFor`.
4) Narrow down the domain class of property `golem:GP0_has_feature` to `ecrm:E28_Conceptual_Object` and keep `golem:G2_Feature` as range.
