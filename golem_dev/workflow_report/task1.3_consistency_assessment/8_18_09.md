

## Attributes assignment issue

The property `golem:GP0_has_feature` (aligned with `dul_region:hasRegion`) has been designed to assign attributes to both characters and textual entities.

Currently, the property has as domain the closest common superclass of `ecrm:E89_Propositional_Object` (used to model textual content such as works and narrative units) and `golem:G1_Character`, which is subclass of `ecrm:E28_Conceptual_Object`. Its range is `golem:G2_Feature` (aligned with `dul_region:Region`), which is specialized into the disjoint classes `golem:G18_Textual_Feature` and `golem:G17_Character_Feature`.

Plus, there are restrictions on both `ecrm:E89_Propositional_Object` and `golem:G1_Character` in order to force, when property `golem:GP0_has_feature` is used, their range to be `golem:G18_Textual_Feature` and `golem:G17_Character_Feature` respectively.

This modeling allows feature assignment to works and narrative units (subclasses of `ecrm:E89_Propositional_Object`) as well as to characters, which is intended. However, `ecrm:E89_Propositional_Object` also includes `golem:G0_Character-Stoff`, a sibling class of `golem:G1_Character`. Character-Stoff represents the infinite, transmedial potential of a character across all actual and possible manifestations, encompassing all conceivable versions, actions, roles, and attributes while remaining open-ended and impossible to fully delineate.

Because of this definition, assigning concrete features or attributes to instances of `golem:G0_Character-Stoff` is conceptually inappropriate. Ideally, this restriction should be enforced at the OWL level.

The modeling goal is therefore to allow feature assignment only to characters and subclasses of `ecrm:E89_Propositional_Object` (particularly works and narrative units), while preventing feature assignment to `golem:G0_Character-Stoff`.



### Choosen Solution - Union domain + explicit disjointness

```turtle
golem:GP0_has_feature rdf:type owl:ObjectProperty ;
    rdfs:domain [ rdf:type owl:Class ;
                  owl:unionOf ( ecrm:E89_Propositional_Object
                                golem:G1_Character )
                ] ;
    rdfs:range golem:G2_Feature .

golem:G0_Character-Stoff rdf:type owl:Class ;
    owl:disjointWith golem:G1_Character ,
				     lrmoo:F1_Work ,
```

## Ontological Criteria for `owl:disjointWith` Application (OntoClean Framework)


Based on the formal ontological framework by Guarino & Welty (2001), declaring two classes $\phi$ and $\psi$ as disjoint ($\phi$ `owl:disjointWith` $\psi$) is ontologically well-founded if they possess mutually exclusive essential characteristics.

### 1. Necessary Condition for Disjointness


**Incompatible Essential Properties**:

   * **Rule**: A class for which a property $P$ is **essential** (must hold for all instances at all times) is disjoint from a class for which $P$ is **anti-essential** (i.e. contingent).
   * *Example*: `LIVING BEING` (life is essential) vs. `PHYSICAL OBJECT` (life is non-essential, as a corpse continues to exist as a physical object after death).

### 2. Sufficient Criteria for Applying Disjointness



1. **Incompatible Identity Conditions (ICs)**:
   
   * **Rule**: Classes carrying different, non-interchangeable criteria for individuation or re-identification over time are necessarily disjoint.
   * *Example*: `ORGANIZATION` (non-extensional IC: retains identity when members change) vs. `GROUP` (extensional IC: loses identity if a member changes).

2. **Incompatible Unity Conditions (UC / Anti-Unity)**:
   
   * **Rule**: A class carrying Unity $(+U)$ cannot share instances with a class carrying Anti-Unity $(\sim U)$ or an incompatible unifying relation.
   * *Example*: `PHYSICAL OBJECT` ($(+U)$, countable essential whole) vs. `AMOUNT OF MATTER` ($(\sim U)$, cannot be an essential whole).

If one of these two conditions holds, classes must be declared disjoint.
