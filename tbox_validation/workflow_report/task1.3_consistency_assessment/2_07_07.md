### Extending Imported Ontologies Without Duplicating Semantics

When reusing properties or classes from imported ontologies, it is generally preferable to add only ontology-specific annotations (such as `rdfs:comment`, `skos:example`, or additional labels) rather than restating the imported formal axioms (`rdfs:domain`, `rdfs:range`, `owl:inverseOf`, `owl:TransitiveProperty`, etc.).

Restating imported semantics locally introduces redundant axioms and can make maintenance more difficult. In ontology editors such as Protégé, the same property may then appear with duplicated domain/range declarations, even though the semantics are unchanged. More importantly, if a local redeclaration accidentally differs from the imported one, OWL combines the constraints, potentially introducing unintended inferences or inconsistencies.

A common best practice is therefore:

- Keep formal semantics in the ontology that originally defines the term.
- Add domain-specific documentation and examples (via rdfs:comment or ) locally through annotations.
- Create a new subproperty only when the local ontology genuinely requires specialized semantics that differ from the imported property.

This approach preserves a clear separation between reused foundational semantics and ontology-specific conceptualization, while minimizing the risk of semantic drift and ontology maintenance issues.
