
## Use of owl:sameAs as mapping between ecrm and cidoc

From [OWL Web Ontology Language Reference](https://www.w3.org/TR/owl-ref/#equivalentClass-def) (OWL 1):

"NOTE: The use of owl:equivalentClass does not imply class equality. Class equality means that the classes have the same intensional meaning (denote the same concept). Real class equality can only be expressed with the owl:sameAs construct. As this requires treating classes as individuals, class equality can only be expressed in OWL Full."


`owl:sameAs` mapping has been introduced in 2023 ([git commit](https://github.com/erlangen-crm/ecrm/tree/master) ecrm_231027.owl), when OWL 2 was already available.


[OWL 2](https://www.w3.org/TR/2012/REC-owl2-primer-20121211/#a_EquivalentClasses) introduced "punning" (using the same IRI as a name for both a class and an individual) precisely to relax the old separation between class names and individual names holding in OWL 1 DL, in order to make OWL 2 DL much closer to OWL FULL. In OWL 2 DL, the same IRI may be used both as a class and as an individual, and the Direct Semantics treats these uses as completely separate entities.

Therefore the fact that Protege reasoner infer that all ecrm and cidoc constructs are also individuals do not generate inconsistency.


## Check whether GOLEM implementation of LRMoo is achievable also in EFRBRoo

### Preliminary issues

EFRBRoo imports the unversioned ECRM namespace (http://erlangen-crm.org/current/), but Erlangen guidelines explicitly recommend to use versioned namespace instead, for the sake of reasoning and maintainability. Therefore if we use EFRBRoo, unversioned ECRM will be indirectly imported as well, and EFRBRoo will inherit unversioned ECRM formal semantics, loosing the connection with versioned ECRM, which we map to DOLCE. Therefore DOLCE formal semantics will not reach FEFRBRoo.


### EFRBRoo compatibility with GOLEM implementation of LRMoo



**Properties**:

| Properties         | LRMoo                                       | EFRBRoo                                                   |
| ------------------ | ------------------------------------------- | --------------------------------------------------------- |
| `is_realised_in`   | domain:F1_Work<br>range:F2_Expression       | domain:individual_work<br>range:self-contained_expression |
| `R5_has_component` | domain:F2_Expression<br>range:F2_Expression | domain:expression<br>range:self-contained_expression      |

Therefore:

**Classes**:

| Class      | LRMoo      | EFRBRoo                   |
| ---------- | ---------- | ------------------------- |
| `Work`       | Work       | individual_work           |
| `Expression` | Expression | self-contained_expression |
